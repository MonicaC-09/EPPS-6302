Part C: Data Collection Plan

A good data collection plan ensures your web scraping is legal, reliable, and reproducible. Here’s my approach and the key principles to considered when doing Web Scraping Research is:

  1. Legal & Ethical Compliance

Before Scraping, the first is to plan the needed data, where to find it, and if scraping is allowed, we can do this through the robots.txt and Terms of Service, and how often the data is updated, and cite the source properly.

  1. Data Quality Assurance

    After scraping the quality of the data must be assurance through multiple ways which are run automatically through the code, easily creates professional tables, real validation of the data, and shows data quality that the scraping worked correctly:

    i. Basic Validation Checks: Row Count Verification, Column completeness, Realistic values, No duplicates, Missing data count, Correct Data Count.

    ii. Cross-Source Validation: to calculate the correlations between three key variables, to show how well the variables agree, prove data reliability for a correlation >0.99.

    iii. Outlier Detection: identifies countries with >10% different between sources, Flags potential data quality issues, and shows which countries need closer examinations

    iv. Reasonableness Checks: for descriptive statistics, confirms valies, and no negative or large values

    v. Data Completeness Analysis: shows how many the subject of the data have all sources, categorizing for complete, mostly complete, limited, none, percentage breakdown

    vi. Missing Data Patterns: Examples of the data subject with missing values, to help explain why there is data missing

  2. Best Practices

For example, in my case Wikipedia allows for scraping for research purposes, I only made one requests for the GDP data, I did not made bulk requests for hundreds of pages, I believed it is cited properly.
